# [DESIGN] 이벤트 기반 상태 갱신 및 자율적 자산 관리 시퀀스 설계 보고서 (v1.0)

본 보고서는 터미널의 자산 변동 이벤트(주문 체결, 삭제, 신규 생성 등) 발생 시에만 구조적 상태를 갱신하고, 변동이 없는 평시에는 등록된 자산별로 진트/익트 등 핵심 트레이딩 기능을 독자적으로 수행하는 **'이벤트-운영 분리형 시퀀스'**를 설계합니다.

---

## 1. 설계 배경
터미널의 모든 자산을 매 틱(Tick)마다 전수 조사하는 것은 리소스 낭비이며, 동기화 지연을 초래할 수 있습니다. 따라서 **[구조적 동기화(Sync)]**와 **[연속적 운영(Management)]**을 분리하여 시스템의 효율성과 반응성을 극대화합니다.

---

## 2. 듀얼 루프 시퀀스 구조 (Dual-Loop Architecture)

### 2.1 [Event-Loop] 구조적 동기화 (Structural Sync)
*   **트리거**: `OnTrade()`, `OnTradeTransaction()`, 또는 주기적 `OnTimer()`.
*   **역할**: 터미널의 실물 자산과 엔진 내부 세션 풀의 '구조적 일치'를 보장.
*   **주요 작업**:
    *   **신규 바인딩**: 새로운 티켓(SID 포함) 발견 시 세션 생성.
    *   **상태 전이**: 오더 체결 감시 시 포지션 세션으로 전환.
    *   **세션 종료**: 자산 부재 및 히스토리 확인 후 세션 풀에서 제거.

### 2.2 [Logic-Loop] 연속적 운영 (Operational Management)
*   **트리거**: 매 `OnTick()` 및 고빈도 `OnTimer()`.
*   **역할**: 이미 등록된(Bound) 자산들에 대해 개별 SID 단위로 트레일링 로직 수행.
*   **주요 작업**:
    *   **오더 관리자**: 진트(Trailing Entry) - 극점 갱신 및 가격 개선.
    *   **포지션 관리자**: 익트(Trailing Stop) - 수익 감시 및 SL 전진.

---

## 3. 상세 프로세스 시퀀스 (Process Sequence)

### STEP 1: 변동 이벤트 감지 및 갱신 (Sync Phase)
자산 관리자(`OrdMgr`, `PosMgr`)는 터미널로부터 이벤트 수신 시 다음과 같이 상태를 동기화합니다.
1.  터미널 자산의 총 수 또는 티켓 목록 변경 확인.
2.  변경이 감지된 경우에만 `ScanAndBind()`를 실행하여 내부 세션 리스트를 최신화.
3.  세션 객체의 `IsDirty` 플래그 또는 `Ticket` 속성을 갱신하여 운영 준비 완료.

### STEP 2: 자율적 관리 실행 (Management Phase)
구조적 변동이 없는 평시 루프에서는 다음과 같이 동작합니다.
1.  **Iterate Sessions**: 현재 세션 풀에 등록된 모든 SID를 순회.
2.  **Asset Health Check**: 각 세션이 가리키는 티켓이 여전히 유효한지 가볍게 체크 (`IsOrderExists`, `IsPositionExists`).
3.  **Execute Trailing**:
    *   **PENDING 상태**: `OrderManager`가 진트 로직(Extreme -> Rebound -> Improve) 실행.
    *   **EXECUTED 상태**: `PositionManager`가 익트 로직(Trigger -> Alpha Calc -> Apply) 실행.
4.  **Local Context Update**: 각 SID별로 독립된 컨텍스트(극점 가격, 활성화 여부 등)를 유지하며 로직 수행.

---

## 4. SID 기반 독립적 관리의 이점
*   **결정성 (Determinism)**: 특정 SID의 자산이 터미널에서 사라지지 않는 한, 해당 세션은 독립적으로 자신의 트레일링 목표를 추격합니다.
*   **부하 분산**: 전체 스캔(Full Scan) 횟수를 줄여 CPU 점유율을 낮추고, 틱 반응 속도를 향상시킵니다.
*   **무결성**: 이벤트 기반 갱신을 통해 수동 조작이나 외부 요인에 의한 자산 변동을 즉각적으로 인지하고 관리 모드를 전환합니다.

---

## 5. 예외 상황 처리 (Exception Handling)

| 상황 | 대응 시퀀스 |
| :--- | :--- |
| **이벤트 누락** | `OnTimer` 기반의 '가디언 스캔(Guardian Scan)'이 5~10초 간격으로 강제 동기화 수행. |
| **티켓 번호 변경** | SID가 동일하면 기존 세션에 새로운 티켓을 즉시 바인딩하여 트레일링 연속성 유지. |
| **동시 다발 변동** | 원자적 일괄 처리(Batch Processing)를 통해 세션 풀의 일관성 유지. |

---

## 6. 결론
본 시퀀스 설계는 '이벤트 기반의 정적 구조 관리'와 '틱 기반의 동적 로직 운영'을 분리함으로써, ATSE가 대규모 자산을 관리할 때도 지연 없는 정밀한 트레일링을 수행할 수 있는 기반을 제공합니다. 관리자는 각 자산의 생존 여부만 확인되면 독자적인 관제 모드로 진입하여 트레이더의 개입 없이 최적의 진입과 청산을 수행하게 됩니다.
