# ATSE 로그 파일(시스템 및 SID) 생성 실패 원인 분석 보고서
**날짜**: 2026-05-19
**작성자**: Gemini CLI
**상태**: 완료 (Fix Applied)

## 1. 개요 (Plan)
ATSE(MQL5 EA) 구동 시 시스템 통합 로그(ATSE_*.log) 및 개별 신호 세션 로그(SID-*.log)가 디스크에 물리적으로 생성되지 않는 현상에 대한 원인을 분석하고 해결함.

## 2. 원인 분석 및 진단 (Do)
로그 파일이 생성되지 못한 근본 원인은 **MQL5 파일 시스템 샌드박스 정책**과 **API의 잘못된 사용**에 있음.

### 2.1 MQL5 샌드박스와 경로 생성 제한
- MQL5의 FileOpen 함수는 지정된 파일명에 존재하지 않는 하위 경로(예: ATSE\ATSE_260519.log)가 포함되어 있을 경우, 자동으로 폴더를 만들어주지 않으며 즉시 INVALID_HANDLE을 반환함.
- 사용자가 Common/Files 하위에 수동으로 ATSE 폴더를 만들지 않은 상태에서 EA가 실행되었기 때문에 모든 파일 오픈 요청이 실패함.

### 2.2 폴더 생성 API 오용
- 하위 경로 문제를 해결하기 위해 도입했던 FolderCreate, FolderIsExist 함수들은 MQL5 Standard Library에 존재하지 않는 환각(Hallucinated) 함수이거나 잘못된 시그니처를 사용하여 컴파일 에러를 유발함.

### 2.3 System Logger 의존성 실패 파급
- 시스템 로거 파일 생성 실패 시 초기화 파이프라인에서 적절한 에러 핸들링이 되지 않아, 파일뿐만 아니라 Remote Logger 및 Tab Logger로의 전달 파이프라인(Dispatcher)마저 정상 구성되지 않는 도미노 현상이 발생함.

## 3. 조치 사항 (Check)
문제를 원천적으로 해결하기 위해 하위 폴더 생성 의존성을 완전히 제거함.

### 3.1 파일명 평탄화 (Flattening) 적용
- 수정 전: ATSE\ATSE_%s.log, ATSE\%s-%s.log
- 수정 후: ATSE_%s.log, %s-%s.log
- **설명**: 파일명에서 ATSE\ 하위 경로를 제거하여 Common/Files 폴더 바로 아래에 파일이 직접 생성되도록 변경함. 이는 MQL5에서 가장 안전하고 오류율이 낮은 방식임.

### 3.2 로거 명명 규칙 안정화
- **시스템 로그**: ATSE_260519-070000.log
- **신호(세션) 로그**: 1001-26051912-01-00-1-1-260519-070000.log
- CXFileLogger에서 SID가 "System"으로 들어올 때와 일반 신호 ID로 들어올 때를 명확히 분기하여 직관적인 파일명으로 관리되도록 개선함.

## 4. 향후 대응 (Act)
- MQL5 환경에서 파일 입출력 로직 작성 시, 하위 디렉토리 사용을 최대한 배제하고 Prefix(ATSE_)를 활용한 파일명 평탄화 패턴을 표준으로 채택함.
- 로거 생성 시 INVALID_HANDLE이 반환될 경우 터미널 Experts 탭에 _LastError와 함께 명확한 실패 사유를 노출하여 유지보수성을 확보함.
